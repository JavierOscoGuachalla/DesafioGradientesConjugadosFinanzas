Simulador de ajustes presupuestarios con Gradientes Conjugados Precondicionado (GCP)

Desafío académico individual · Área: Finanzas · Sistema simétrico definido positivo Ax = b con n = 6 categorías de gasto.

Javier Osco Guachalla
1795318
Desarrollo de Sistemas

Síntesis. Una empresa de software debe ajustar el presupuesto anual entre seis categorías de gasto cuando lo que se solicita no coincide con el monto disponible. El ajuste se plantea como un problema de mínimos cuadrados penalizados cuya condición de optimalidad es el sistema lineal (W + L + ρ·𝟙𝟙ᵀ)·x = W·d + ρ·B·𝟙, simétrico y definido positivo. Se resuelve con el método GCP de Suñagua (2020), se contrasta con el GC simple y con un método directo, y se estudian tres escenarios: ideal, bajo estrés y mal condicionado. La página está construida como una aplicación por componentes, con validación matemática de toda entrada y un módulo de pruebas funcionales.

2 Caso de estudio

Contexto financiero, justificación del modelo, procedencia de los datos y arquitectura del software.

Contexto

El área financiera de una empresa de desarrollo de software recibe solicitudes de gasto dᵢ de seis categorías, pero dispone de un monto total B. Se busca la asignación x (en miles de Bs) que:

  • se desvíe lo menos posible de lo solicitado, según la prioridad wᵢ de cada categoría;
  • mantenga proporcionadas las categorías interdependientes (por ejemplo, QA con Desarrollo): penalización kᵢⱼ;
  • respete el techo presupuestario de forma suave, con penalización ρ.

J(x) = ½·Σ wᵢ(xᵢ − dᵢ)² + ½·Σi<j kᵢⱼ(xᵢ − xⱼ)² + ½·ρ·(Σxᵢ − B)²

Anular el gradiente, ∇J = 0, produce Ax = b con A = W + L + ρ·𝟙𝟙ᵀ y b = W·d + ρ·B·𝟙 (W = diag(w), L = laplaciano ponderado de los kᵢⱼ).

Por qué A es simétrica definida positiva

  • W, L y 𝟙𝟙ᵀ son simétricas ⇒ A = Aᵀ.
  • xᵀAx = Σ wᵢxᵢ² + Σi<j kᵢⱼ(xᵢ−xⱼ)² + ρ(Σxᵢ)² > 0 para todo x ≠ 0, porque wᵢ > 0, kᵢⱼ ≥ 0, ρ ≥ 0.
  • Es decir, J es estrictamente convexa y su único mínimo es la solución de Ax = b.

Procedencia de los datos

Los montos, prioridades y penalizaciones son valores ilustrativos calibrados (montos en miles de Bs, de orden de magnitud típico de una pyme de software), no provienen de un registro contable real. Se pueden reemplazar editando A y b en el módulo 4.

3 Formulación

Variables, sistema lineal, interpretación de coeficientes y demostración de simetría y definición positiva.

Variables (n = 6)

xᵢ = monto asignado a la categoría i (miles de Bs).

Interpretación de coeficientes

  • aᵢᵢ = wᵢ + Σⱼkᵢⱼ + ρ: rigidez total de la categoría i (cuánto «cuesta» desviarla de su solicitud, de sus categorías vinculadas y del techo).
  • aᵢⱼ = ρ − kᵢⱼ (i≠j): acoplamiento. ρ los une por el techo común; kᵢⱼ los obliga a moverse juntos (lo reduce).
  • bᵢ = wᵢdᵢ + ρB: «fuerza» que empuja la categoría hacia su solicitud y hacia el techo.
  • Fila i de Ax = b: equilibrio de todas las presiones sobre la categoría i.

9 Módulo de Pruebas (QA)

Pruebas funcionales y matemáticas ejecutadas en tu navegador contra el código real de la página (incluyendo simulación de eventos sobre la interfaz).

Guía de prueba manual (edición dinámica y matriz no válida)
  1. En el módulo 4 cambia cualquier aᵢⱼ: con «Espejar simetría» activo, aⱼᵢ se actualiza y todo se recalcula al instante.
  2. Desmarca «Espejar simetría» y cambia solo a₁₂: el par se marca en amarillo, aparece el aviso de matriz no simétrica y los módulos 6–8 indican «no calculable» sin colapsar.
  3. Pon a₁₂ = a₂₁ = 50 (con espejo): la matriz deja de ser definida positiva y se notifica.
  4. Escribe una tolerancia negativa, ω = 3 o N máx. = 0: se avisa y se usa un valor por defecto.
  5. Pulsa «Restablecer escenario» para volver a los datos originales.
